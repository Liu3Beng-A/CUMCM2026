## 二、P0 硬伤（直接动摇核心结论）

### P0-1：Bootstrap 不是 Prophet-based，与论文描述矛盾

**问题描述**  
- `q1_bootstrap.py:_bootstrap_one_holiday()` 对**原始日级数据**做重采样后，两次独立 Prophet 拟合（含/不含节假日）
- 论文 5.1.5 写的是"Bootstrap 重采样（Prophet 反事实 A/B）"，会误导评委以为 Bootstrap 采样的是 Prophet 后验分布
- 实际是：对原始数据 Bootstrap → 再拟合 Prophet → 两次 Prophet 的 yhat 差值作为节日效应 → 再对差值做 Bootstrap p 值

**更严重**：`q1_robustness_aug.py` 第 120-168 行有**另一套完全不同的 Bootstrap**（节日效应=当天值-前后7天均值，无 Prophet），两套结果不可比。

**修复方案**

| 方案 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| A. 统一为 Prophet-based Bootstrap | 删除 `q1_robustness_aug.py` 里的简化版 Bootstrap，改为对 Prophet 反事实差值做 Bootstrap（与 `q1_bootstrap.py` 保持一致） | 方法统一，与论文描述对齐 | 工作量较大，需重写鲁棒性脚本 |
| B. 统一为简化版 Bootstrap | 删除 `q1_bootstrap.py` 里的 Prophet 双模型，改为用"当天值-前后7天均值"作为节日效应，对原始数据做 Bootstrap | 简单，计算快，无需 Prophet | 与论文描述"Prophet 反事实"矛盾，需同步改论文 |
| C. 论文修正（不改代码） | 将论文 5.1.5 改为"Bootstrap 重采样原始日级数据后拟合 Prophet 双模型"，`q1_robustness_aug.py` 的简化版标注为"稳健性辅助验证" | 工作量最小，不动核心代码 | 论文与 `q1_robustness_aug.py` 仍不一致，评委可发现 |

### P0-2：LOO-CV ρ=1.00 测试的是权重稳健性，不是泛化能力

**问题描述**  
- `q1_generalization.py:loo_cross_validation()` 用 Leave-One-Out 剔除方案后，用训练集（4个方案）的 CRITIC 权重计算被剔除方案的加权综合分
- 统计"有多少训练方案得分低于被剔除方案"来确定预测排名相关性 ρ
- ρ=1.00 的含义：**在已知权重下，被剔除方案的相对排名在训练集内是确定的**——这不是"对未见方案的预测能力"，而是"权重计算对样本量的敏感性"
- 论文 5.1.7 节声称"方法泛化能力稳健，ρ=1.00"，属于方法论层面的根本性误解

**修复方案**

| 方案 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| A. 重新表述论文 | 将"泛化能力验证"改为"权重稳健性验证"，ρ=1.00 的含义改为"不同训练集下权重基本一致" | 工作量最小 | 结论弱了很多（从"泛化"变成"权重稳定"），说服力下降 |
| B. 重新设计泛化测试 | 改为：用时间切分的训练集（上半年）预测下半年各方案的节日效应量级，验证 Prophet 趋势外推准确性 | 真正测试泛化能力 | 需要重写，时间紧张 |
| C. 保持代码，修正论文叙事 | 论文写"权重稳健性（Leave-One-Out 验证）"，不写"泛化能力" | 保留 ρ=1.00 这个好看的数字，修正描述 | 评委如果深读代码仍会发现测试目的不对 |
| D. 删除 LOO-CV 章节 | 直接删除 `q1_generalization.py` 的 LOO-CV 部分和对应论文章节 | 最干净 | 少了一个验证方法 |

### P0-3：异常日 Z=1.69 来自退化路径，阈值无依据

**问题描述**  
- `q1_robustness_aug.py` 先找 Z>3 的异常日，找不到则退化到取"8月消费额最大"
- `Z=1.69` 来自退化路径（8月均值 vs 8月标准差），**不是统计显著异常**（通常 Z>1.96 才在 α=0.05 下显著）
- 论文和 README 把 Z=1.69 作为鲁棒性检验依据，评委复现会发现这个值不显著

**修复方案**

| 方案 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| A. 改用 IQR 法定位异常日 | 用 `Q3 + 1.5*IQR` 定位异常，Z=1.69 改为 IQR 倍数（如 1.5 倍 IQR） | 有统计依据 | IQR 方法下 2025-08-21 不一定被识别为异常，需重新找 |
| B. 直接降低 Z 阈值 | 改为"Z>1.5"或"Z>1.0"，接受"中度异常"定位 | 简单，改一行代码 | 论文叙事需调整（不能叫"异常"，改为"消费高峰日"） |
| C. 接受退化路径，修正论文叙事 | 论文写"8月消费高峰日（Z=1.69）"而非"异常日"，去掉 Z-Score 的统计显著性暗示 | 最小改动 | Z=1.69 作为鲁棒性检验依据的意义大幅削弱 |
| D. 放弃异常日检验 | 删除整个鲁棒性章节，改为用 Bootstrap CI 宽度作为稳健性证据 | 最干净 | 少了一个验证维度 |

## 三、P1 问题（影响评分可信度）

### P1-1：两套评分函数口径不一致

**问题描述**  
- `score_design_quality()` 等4个函数：计算**全公司聚合指标**的评分（关键词有效率 60%→57.2分）
- `_score_per_plan()`：用硬编码公式模拟各方案的**逐方案评分**（如 `s_design = 100 - abs(avg_top - 0.55) * 200`）
- CRITIC 权重基于 `_score_per_plan()` 的5×4矩阵，但论文展示的是**维度级全局评分**，两者不同口径

**修复方案**

| 方案 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| A. 统一为维度级评分 | 删除 `_score_per_plan()`，CRITIC 权重改为基于4个维度函数在全公司数据上的评分矩阵（5方案×4维度） | 口径统一，论文与代码一致 | CRITIC 权重会有变化，排名可能小幅调整 |
| B. 统一为方案级评分 | 删除4个维度评分函数，所有评分改为用 `_score_per_plan()` 逻辑（硬编码模拟） | 计算逻辑统一 | 硬编码公式（0.55、500、50等）无解释，评委可追问 |
| C. 论文标注口径 | 论文中明确区分"维度级评分（用于展示）"和"方案级评分（用于 CRITIC）"，不做合并 | 工作量小 | 两套数字并存，评委可能困惑 |

### P1-2：行业阈值表（INDUSTRY_THRESHOLDS）无引用来源

**问题描述**  
- `q1_scoring.py` 第 44-57 行的9个指标阈值声称"综合 SEM 行业经验值"，无任何文献/报告引用
- CPC 失格上界 3.00 元远超实际均值 1.71 元，阈值设定过于宽松
- 评委若问"凭什么 A≥85 而不是 A≥90"无法回答

**修复方案**

| 方案 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| A. 用数据集实际分位数替代行业阈值 | 阈值改为"基于数据自身分布的百分位数"（如"前20%→A，后20%→C/D/E"） | 有数据支撑，可复现 | 不再有行业标准参照，论文叙事需调整 |
| B. 增加论文脚注说明 | 阈值注明"综合行业经验与本题数据分布联合确定"，不列具体引用 | 最少改动 | 无真实引用，评委追问仍无法回答 |
| C. 删除行业阈值评分轨道 | 只保留"百分位+Z-Score 双轨评分"，删除行业绝对阈值 | 减少一个评分维度 | 评分体系变薄，少了一个方法 |
| D. 补充文献引用 | 查找 SEM 行业报告（如 WordStream、BrightEdge 每年发布的 CPC/CTR 基准），补充引用 | 最符合学术规范 | 时间紧张，查找引用本身需时间 |

### P1-3：Prophet 反事实置信区间计算有误

**问题描述**  
- `q1_prophet.py` 第 71-72 行：
  ```python
  compare['节日贡献下界'] = compare['实际值'] - compare['无假日预测上界']
  compare['节日贡献上界'] = compare['实际值'] - compare['无假日预测下界']
  ```
- 这计算的是"实际值在无节假日预测区间内的偏移"，**不是**节日贡献本身的置信区间

**修复方案**

| 方案 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| A. 改用 Bootstrap 直接采样节日贡献分布 | 对每日节日效应做 Bootstrap，直接取 2.5%/97.5% 分位数作为 CI | 正确，学术规范 | 需重写 Prophet CI 计算逻辑，计算量增加 |
| B. 删除置信区间展示 | 只画点估计（节日贡献均值），不加 CI 范围 | 最简单 | 图表信息减少，Prophet 图说服力下降 |
| C. 修正论文描述 | 论文写"图中阴影为 Prophet 预测区间，不代表节日贡献置信区间" | 最少改动代码 | 论文需仔细措辞避免歧义 |

### P1-5：74 个 Bootstrap 检验无多重比较校正

**问题描述**  
- 37节日 × 2指标 = 74次检验，p<0.05 无校正的假阳性率约 3.7%（~2.8个假阳性）
- 75.7% 显著率（56/74）在 FDR 校正后可能显著下降

**修复方案**

| 方案 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| A. 加 Benjamini-Hochberg FDR 校正 | 用 `statsmodels.stats.multitest.multipletests` 做 BH 校正，比较校正后 p<0.05 的数量 | 学术规范，控制假阳性 | 显著节日数量可能减少（56→约50），节日扣分逻辑需调整 |
| B. 用 Bonferroni 校正 | 保守，但 74 次检验后阈值为 0.05/74≈0.00068，基本没有节日显著 | 最保守 | 几乎没有节日显著，节日扣分无法执行 |
| C. 不校正，论文加注释 | 写"74 次检验为探索性分析，未做多重比较校正，显著性结果供参考" | 保留现有数字 | 评委可质疑假阳性风险 |
| D. 减少检验次数（合并节日） | 将37个节日按类型合并（如所有购物节合并为一个检验），减少检验数 | 自然减少多重比较问题 | 损失节日特异性，论文叙事变粗粒度 |
